## AI 智能注释 v0.2.0 交付

### 1. AI 配置与安全凭据

- 设置页 AI 模块从占位改为可用的 OpenAI 兼容 Chat Completions 配置：
  - 服务商预设：DeepSeek（`https://api.deepseek.com/v1` / `deepseek-chat`）、OpenAI、SiliconFlow、自定义；
  - Base URL 允许手动填写，自动补全 `/chat/completions`，校验 http/https、主机名、无内嵌用户名/密码/查询参数；
  - Model 允许手动输入任意名称；
  - Timeout 默认 30 秒，范围 5–120 秒；
  - Temperature 可选，留空时请求体不发送该字段，清除时写回 `null`；
  - 测试连接按钮使用当前表单值；允许在保存前使用尚未落库的 API Key 测试；
  - 自动注释开关默认关闭。
- API Key 只写入 **Windows Credential Manager**：
  - 目标：`PataCommands/AI/OpenAICompatible`；
  - 用户名：`pata-commands`；
  - 不写入 `settings.json`、SQLite、JSON 导出、应用日志或命令数据；
  - 前端只显示“密钥已配置/未配置”，不读取、不回显已保存密钥；
  - 保存后输入框清空，留空表示保持现有密钥；清除密钥需确认。
- 设置 schema 从 4 升级到 5，只增加 AI 字段（无 API Key），旧窗口/主题/剪贴板/色板偏好全部保留。
- `AppSnapshot.aiApiKeyConfigured` 由 Rust 读取凭据管理器状态生成，前端不持有密钥。

### 2. Rust AI Service 与请求链路

- 新增独立模块 `src-tauri/src/services/ai/`：
  - `client.rs`：OpenAI 兼容请求、URL 校验、错误映射、超时、JSON 提取；
  - `credentials.rs`：Windows Credential Manager 读写删；
  - `prompt.rs`：中文命令解释 prompt 与不可信命令边界；
  - `repository.rs`：AI 注释和状态持久化；
  - `mod.rs`：配置装配、输出校验、自动注释条件、取消注册表。
- 所有 AI 网络请求均由 Rust 后端发送，React 只通过 Tauri Command 获取结果；未引入前端 fetch 或 Key 暴露。
- 默认请求 `POST {BaseURL}/chat/completions`，使用 `Authorization: Bearer`；不执行命令。
- Prompt 要求：
  - 只输出 JSON，不使用 Markdown 包裹；
  - 简短说明 15–40 个汉字，详细说明突出实际用途；
  - 解释重要参数、执行前提和风险；
  - Shell 只使用 `powershell/cmd/bash/sh/zsh/other/unknown`；
  - 风险等级只使用 `low/medium/high/unknown`；
  - 不确定内容明确说明，不编造；
  - 命令文本作为不可信数据传入，注入式内容不得作为指令执行。
- 首次请求带 `response_format: json_object`；部分模型不支持时仅在 HTTP 400/422 且错误明确指向 `response_format/json_object` 时自动重试一次去掉该字段。
- JSON 解析支持纯 JSON 和 ```json 围栏；字段缺失、内容为空或非 JSON 返回可读错误，不写入数据库。
- 输出长度与条数做上限归一化：简短注释 160 字、详细说明 4,000 字、参数 24 条、前提/风险各 12 条；Shell/风险等级归一化为安全枚举。
- 支持超时、取消、错误提示和手动重试；取消使用按 request id 注册的 oneshot 通道，跨请求不会误取消。
- API Key 不出现在任何错误消息；`AiConnectionConfig` 的 Debug 输出将密钥显示为 `<redacted>`。

- 命令详情新增“AI 解释”区块和“AI 生成注释/重新生成”按钮。
- 点击后显示生成中，可取消；成功后打开预览，不直接写库。
- 预览中可编辑：
  - 简短注释；
  - 详细说明；
  - 参数名和参数说明（可添加/删除）；
  - 执行前提（每行一条）；
  - 风险提示（每行一条）。
- 预览顶部保留只读命令原文，明确“不会修改”；Shell 和风险等级仅展示建议，不自动改写命令 Shell。
- 已有手写注释时提供并强制选择：
  - **保留原注释（默认）**：AI 数据单独保存，手写 title/description 不变；
  - **追加 AI 内容到现有注释**：保留手写文本，在 title 追加 AI 简短说明，在 description 追加“AI 补充”；
  - **用 AI 内容替换现有注释**：用用户确认后的 AI 简短/详细说明替换手写字段。
- 命令原文 `command` 在任何模式下都不被修改；`content_hash` 不变。
- 保存前再次计算并比对当前命令哈希；若命令在生成期间已修改，返回 `AI_STALE_COMMAND`，不会覆盖。
- 预览“重新生成”不保存；未点击“应用并保存”不会写数据库。
- 完整注释存储于独立 `ai_annotations` 表；命令状态更新为 `ready`。
- 详情展示简短注释、详细解释、参数、执行前提、风险提示、建议 Shell、风险等级和可折叠 AI 模型信息；命令原文始终在最上方，不被解释遮挡。
- 若命令在生成后内容被修改，详情显示“AI 注释可能过期”，并提示重新生成。
- 快捷面板和命令列表第二行显示简短注释：手写 title 优先，没有手写注释时使用 AI 简短注释；无注释且未生成时不显示占位文字。
- 自动生成中在第二行显示轻量“AI 生成中”状态，不增加卡片高度层级。

### 4. 自动注释

- 仅从剪贴板保存新命令时触发；默认关闭，用户主动开启。
- 保存流程：
  1. 命令先写入 SQLite 并立即返回；
  2. 本地检查自动开关、凭据、配置、手写注释、已有 AI 注释、敏感内容；
  3. 标记 `ai_annotation_status = pending` 并刷新界面；
  4. 异步请求 AI；
  5. 成功保存 AI 注释并置为 `ready`，失败置为 `failed`，命令始终保留；
  6. 完成后通过 `data://commands-changed` 刷新快捷面板和管理器。
- 自动注释不弹出编辑表单，不阻塞保存和复制。
- 重复保存返回已有命令，`created = false`，不会再次触发 AI。
- 已有手写注释、已有 AI 注释、`pending`/`ready` 状态和疑似敏感内容均跳过自动生成。
- 自动失败只更新状态，不弹出表单；用户仍可在详情手动重新生成。
- 进程在请求中退出会遗留 `pending`；启动时统一恢复为 `failed`，允许重试，不会永久卡住。
- 应用启动后自动恢复逻辑；测试中自动任务从 `pending` 到 `ready` 约 1.65 秒，保存请求未被网络阻塞。

### 5. 批量生成（仅无注释命令）

- 完整管理器多选后提供“批量 AI 注释 (N)”按钮，N 为所选命令中真正可生成的数量。
- 批量条件：
  - 无有效手写 title、无手写 description；
  - 无已有 AI 注释；
  - 状态不是 `pending`/`ready`。
- 已有注释的命令直接跳过，按钮数量和对话框统计都会体现；不重复请求、不重复计费。
- 批量对话框明确显示“可生成 / 已有注释 / 生成中”数量、API 用量提示和敏感内容拦截说明。
- 点击开始后按所选顺序逐条请求，避免并发覆盖和突发并发；成功结果直接保存，不弹出单条预览。
- 进度显示完成总数、成功、失败、敏感跳过，并可停止；停止会取消当前请求。
- 单条失败不影响其他命令；失败命令保持原样，可以重新选中再试。
- 批量模式不自动发送疑似包含密码、Token、私钥或其他凭据的命令。
- 本轮先用 3 条无注释命令验证 3/3 成功；随后用 3 条无注释 + 2 条已有注释验证统计为“3 可生成 / 2 已有注释”。

### 6. 数据模型、迁移与恢复

- SQLite schema 从 3 升级到 4，新增独立 `ai_annotations` 表：
  - `id`、`command_id`（UNIQUE，外键 `ON DELETE CASCADE`）；
  - `short_description`、`detailed_description`；
  - `parameters_json`、`requirements_json`、`warnings_json`；
  - `suggested_shell`、`risk_level`、`provider`、`model`；
  - `command_content_hash`、`prompt_version`、`generated_at`、`updated_at`。
- 保留 `commands.ai_annotation_status`，取值为 `none/pending/ready/failed`。
- AI 注释与手写 `commands.title/description` 分表保存。
- 数据库迁移版本化、事务内执行；迁移前生成 `pre-migration-v3-*` 备份；不重建、不删除旧命令。
- 命令更新时更新 `content_hash`；读取 AI 注释时实时比较哈希并返回 `isStale`，不修改原始命令内容。
- 删除命令采用既有软删除，AI 注释随数据库备份保留；数据库恢复会复制 `ai_annotations`，旧备份没有表时回退为无注释并对残留状态归一化。
- JSON 导出仍为 schema 3，且不包含 AI 注释表；API Key 不进入 JSON 导出。数据库一致性备份/恢复包含 AI 注释。
- 设置 schema 4 → 5 迁移有独立测试，只增加 AI 配置字段并保留所有旧偏好。

### 7. 安全与异常处理

- 失败场景已覆盖：
  - 未配置 Base URL/模型/API Key；
  - 401/403、404、429、4xx、5xx、网络失败、超时；
  - 非 JSON、缺失字段、空内容；
  - 请求取消；
  - 命令在生成后变化；
  - 命令已删除；
  - 自动任务中断/失败；
  - 敏感内容手动确认；
  - 批量逐条失败隔离。
- 敏感命令手动生成时必须二次确认，确认文案包含服务商、模型和“完整命令原文将发送到第三方、无法撤回”；自动和批量路径不会发送。
- AI 输出只作为文本展示，未使用 `dangerouslySetInnerHTML`，不执行、不注入命令或业务字段。
- API 请求不记录完整命令；应用没有新增命令/请求日志。
- Key 只在 Rust 内存中用于 Authorization 头；设置文件和数据库扫描均无命中。

### 10. 已知边界

- 真实 Win32 剪贴板读取在本轮验收时被其他程序持续占用，无法设置/读取当前剪贴板；自动注释流程改用 Windows 系统剪贴板历史保存入口完成真实验证，覆盖的是同一 `save_clipboard_text` 与异步链路。
- 批量生成由前端逐条驱动，不是后端持久化队列；退出应用会终止当前批次，未处理的命令保持原状态。
- 自动注释请求没有单独的停止按钮；手动生成和批量当前请求可取消。
- 批量失败不自动重试；关闭后重新选择仍可重试。
- JSON 命令导出当前不包含 `ai_annotations`；数据库备份/恢复包含 AI 注释。
- 敏感检测仍是启发式，不能保证覆盖全部密钥格式；自动/批量路径会保守跳过，手动路径必须确认。
- Prompt 版本固定为 `annotation-v1`；本轮未做模型下拉列表，Model 允许任意手输。
- 服务商预设只内置 DeepSeek/OpenAI/SiliconFlow，其他兼容服务使用“自定义”。

### 2. 排序修复与真实持久化

- 定位并修复三个真实原因：
  - **红色禁止光标根因**：Tauri 窗口默认 `dragDropEnabled: true`，会替换 WebView2 的原生拖放处理器。Tauri 官方 schema 明确说明 Windows 上使用前端 HTML5 拖放必须关闭该 handler。现在 `tauri.conf.json` 设置 `"dragDropEnabled": false`；应用没有使用 Tauri 原生文件 drop，因此不影响文件导入。
  - 分类树此前只监听 `dragover`；原生拖拽进入目标后若没有继续移动，不会产生可放置状态，drop 不触发。现在分类节点、未分类入口、列表命令行和树命令行都处理 `dragenter` 与 `dragover`。
  - 实现管理器“上移/下移”，此前菜单中没有这两个操作。
- 上移/下移使用当前可排序范围（列表或树内同分类）交换相邻命令，前端立即更新，调用 `reorder_commands` 单事务持久化；失败恢复原数组。
- 自定义排序下允许排序；最近/名称/搜索/收藏/标签等含义不明确的场景禁用排序并显示简短提示。拖入分类不受排序模式限制。
- SQLite 查询补齐稳定次级排序：
  - 自定义：`sort_order, updated_at DESC, title, id`
  - 最近：`last_used_at` 空值/倒序、`updated_at DESC, id`
  - 名称：`title, sort_order, id`
- 实测拖拽和上移/下移后重启顺序保持；分类筛选下只改变该列表的槽位，不影响其他分类。

## 阶段三交付

### 1. 数据库与设置迁移

- SQLite `user_version` 从 1 迁移到 2。
- `commands` 新增：
  - `source_type`：默认 `manual`；
  - `content_hash`：FNV-1a 稳定指纹；
  - `ai_annotation_status`：默认 `none`，仅预留。
- 新建 `clipboard_entries`：独立于命令表，存本地临时历史；唯一内容指纹、复制时间、敏感标记、可选命令关联。
- 迁移前创建 `pre-migration-v1` 备份；迁移完成后为旧命令回填内容指纹。
- 设置 schema 从 2 升到 3：新增监听开关、历史上限（默认 100）、保留天数（默认 7）、复制后自动隐藏。
- 实际在旧数据库/旧设置上启动，确认 schema 2 数据库与 schema 3 设置迁移成功，旧命令保留。

### 2. 当前剪贴板

- Rust Win32 读取 `CF_UNICODETEXT`，保留原始 CRLF、空格、缩进、引号和中文。
- 剪贴板被其他程序短暂占用时重试；读取失败返回错误，不清空本地历史。
- 空文本、非文本（图片）返回空，不导致窗口崩溃。
- 快捷面板唤出时读取，当前内容置顶。

### 3. Windows 系统剪贴板历史

- 实际验证官方 WinRT：
  - `Clipboard.IsHistoryEnabled()`；
  - `Clipboard.GetHistoryItemsAsync()`；
  - `DataPackageView.GetTextAsync()`。
- 在 Tauri 2 + Rust 下通过独立 blocking task + `CoInitializeEx(STA)` 成功调用。
- 实际开发版返回 `available`、16 条可读历史；非文本条目逐条跳过，不影响其他条目。
- 通过临时关闭 Windows `EnableClipboardHistory` 验证 `disabled` 状态；当前剪贴板和本地历史保存仍成功，随后恢复原系统设置。
- 未使用 Win+V 模拟、截图识别或未公开数据库；没有调用删除/修改 Windows 历史。
- 系统历史读取失败/关闭时显示明确提示。
- `HistoryChanged` 未订阅；面板打开、本地剪贴板事件、保存/清空和数据变更会触发重新读取。

### 4. 本地剪贴板监听

- Windows `AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE`，使用专用 message-only 窗口。
- 120 ms 合并窗口处理后端工作线程，连续复制不会堆积重复事件。
- 内容相同的记录只更新时间，不重复插入。
- 监听开关可配置；关闭后停止新增，当前剪贴板仍可读取/保存。
- 自身复制前设置 1.5 秒抑制窗；实测应用内复制不会进入本地历史，随后外部复制相同文本会进入。
- 敏感内容不缓存；空文本、图片、超长文本跳过。
- 上限和保留天数可配置；启动、读取和写入后清理。
- 一键清空只删 `clipboard_entries`，永久命令保留。
- 本地历史仅存本机 SQLite，明文，没有加密。

### 5. 一键保存

- 快捷面板保存不弹表单，不要求标题、说明、Shell、分类、标签。
- 自动标题：首个有意义行，去掉常见提示符，最多 80 字。
- Shell：明确 PowerShell / CMD / Bash 特征才猜测；跨平台命令用 `unknown`。
- 分类/标签/说明为空；来源记录为 `clipboard_current` 或 `clipboard_history`。
- 严格原文去重，返回已有命令 ID；不重复创建。
- 保存与 Favorite 分离；保存不会自动收藏。
- 保存后不关闭面板，按钮立即变为“已保存”；点击已保存按钮跳转命令编辑器。
- 保存不触发 AI/网络；AI 未配置不影响保存。

### 6. 敏感内容

- 私钥头、password/passwd、Token/API Key、Bearer、AWS、带凭据连接串等启发式检测。
- 本地监听不缓存敏感内容。
- 当前/系统历史条目显示“敏感”标记。
- 点击保存先弹确认；取消不写库，确认后才写入。
- 没有 AI 发送路径。

### 7. 快捷面板重构

- 三视图：剪贴板 / 命令库 / 收藏，默认剪贴板。
- 当前剪贴板置顶；系统历史保留 API 顺序；本地历史倒序；跨来源按原文去重。
- 卡片显示来源、相对时间、敏感标记、保存/已保存、复制。

## 关键决策

1. **临时历史与永久命令分离**：`clipboard_entries` 可清空，`commands` 不受影响；系统历史只读。
2. **原文是唯一事实**：标题/Shell/预览/指纹只用于辅助；保存和复制的 `command` 保持原样。
3. **严格去重**：不做空白/大小写归一化，避免把不同参数或引号误判为同一命令。
4. **官方 API 优先**：系统历史使用 WinRT，不使用 Win+V 模拟、截图或未公开数据库。
5. **敏感内容可保存但不自动外发**：保存需要明确确认；AI 自动/批量路径跳过，手动生成必须二次确认。
6. **事件驱动一致性**：命令和剪贴板各自 revision，前端在事件后读取权威 SQLite 状态。
7. **保存不阻塞**：SQLite 成功即返回；自动 AI 只能异步触发。
8. **外观模式分离**：命令自己的颜色与分类颜色分别存储；“使用所在分类颜色”是实时引用模式，不是复制颜色值，取消后恢复自己的颜色。
9. **颜色 token 集中**：预设和自定义颜色的浅色/深色派生全部在 `palette.ts`，组件只消费 CSS 变量，避免在视图中硬编码主题分支。
10. **命令优先展示**：命令原文是主内容，`title` 仅作简短注释、`description` 作详细说明；自动生成的重复标题不渲染，不迁移或删除旧字段。
11. **共享展示组件**：快捷面板、管理器列表、树、概览和拖拽预览统一使用 `CommandPrimary`，只在一个地方调整字号、截断和注释层级。
12. **目录命名只改 UI**：系统默认目录仍是 `NULL`，用户目录仍是 UUID；显示“目录结构/默认”不依赖名称判断，也不改数据库结构。
13. **AI 注释与手写说明分表**：`ai_annotations` 独立保存，命令手写 title/description 不被后台任务覆盖；追加/替换只在用户明确确认后执行。
14. **密钥与设置分离**：API Key 只在 Windows Credential Manager，settings.json 只保存非敏感配置。
15. **AI 结果不可直接执行业务修改**：Rust 校验结构、长度和枚举；命令原文只读，保存前用内容哈希复核。
16. **自动/手动共享 Service**：生成、校验、保存、取消和错误映射复用同一 Rust 路径，前端只负责状态和预览。

## 提示词库 v0.2.0 增量

### 1. 数据与迁移

- 数据库 `v4 → v5`，新增：
  - `prompts`：正文、可选标题、目录、收藏、背景色、排序、使用次数、最近使用、软删除；
  - `prompt_categories`：独立目录树，复用 Lucide 图标/颜色/排序能力；
  - `prompt_tags`：与命令共享 `tags` 词表，关联表独立；
  - `prompts_fts`：FTS5 + 三个同步触发器。
- 没有给 `commands` 增加 `type=prompt`，也没有重建数据库；已有 7 条命令、剪贴板历史和 AI 注释原样保留。
- 非空旧库迁移前自动 `VACUUM INTO` 生成 `commands.db.pre-migration-v4-*.bak`。
- Repository/Service/Tauri command 独立为 `services::prompts` 与 `commands::prompts`；命令与提示词分别发 `data://commands-changed` / `data://prompts-changed`。

### 2. 提示词管理器

- 侧栏新增「提示词库」，拥有独立目录树和独立筛选状态；切换命令库/提示词库时只显示当前库的目录。
- 三栏布局：目录树 / 文本卡片列表 / 完整原文预览；列表支持单击选中、双击复制、右键、拖拽排序、拖到侧栏目录、Ctrl/Shift 多选、按选择或列表顺序批量复制。
- 文本卡片展示可选标题、2–4 行正文、收藏、目录路径、标签和使用次数；长文本不会使用命令行代码框或行号。
- 右侧详情使用纯文本、自动换行、可选择、可滚动，保留原始换行/缩进；只有复制、编辑、收藏、删除和目录/标签。
- 编辑器是独立的多行纯文本编辑器，不复用命令表单；标题可选、正文必填、目录/标签/颜色/收藏可选，支持 Ctrl+S、Esc、未保存确认和原生撤销重做。
- 背景颜色默认中性；只有用户明确设置才显示淡马卡龙色。目录外观复用现有分类图标/颜色弹层，但写入 `prompt_categories`。

### 3. 快捷面板

- 第一层内容类型：剪贴板 / 命令库 / 提示词库；第二层筛选：全部 / 最近使用 / 收藏。避免把标签挤在一行。
- 命令卡片保持原样；提示词使用专属卡片：
  - 默认约 5 行正文预览；
  - 单击复制完整原文；
  - 悬停复制/编辑/收藏；
  - 展开后在当前面板内显示更长内容并滚动，`Esc` 先收起；
  - 右键复制、编辑、收藏、设置背景、移动目录、在完整提示词库查看、删除。
- 键盘保留：上下选择、Enter 复制、Esc 收起/清空/隐藏。
- 剪贴板条目的「保存」主按钮仍一键保存为命令；旁边下拉菜单新增「保存为提示词」。提示词保存不打开表单、标题取首行、默认目录、严格去重、敏感内容二次确认。
