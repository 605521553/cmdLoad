# Pata Commands — UI/UX 整体优化任务书

## 一、项目背景与改版目标

目前 Pata Commands 已实现快捷面板、完整管理界面、命令库、剪贴板历史、分类树、右键菜单、拖拽管理等基础功能。

现有界面整体比较简陋，虽然功能已初步具备，但仍存在布局松散、空白过多、信息层级不清晰、操作入口分散等问题。

本次改版的核心目标：

**将 Pata Commands 打造为一款类似 Raycast、Codex、VS Code 的现代化、简洁、紧凑、高效的 Windows 桌面开发者工具。**

本次主要优化 UI/UX，不改变已有的核心业务架构。

### 设计参考

- **Raycast**：参考快捷面板的搜索、命令列表、键盘交互、悬停效果和快捷操作。
- **Maccy**：参考简洁的剪贴板历史列表和轻量化操作。
- **VS Code**：参考多级分类树、文件夹管理、拖拽排序和右键交互。
- **Pieces for Developers**：参考代码片段管理、内容预览和详细信息展示。
- **OpenAI Codex**：参考整体配色、字体、留白、按钮和现代化简约设计语言。

不要完全复制某一款软件，而是结合 Pata Commands 的实际功能形成一致的设计风格。

## 二、整体视觉设计规范

### 2.1 设计原则

1. 简洁、现代、克制，避免传统管理后台风格。
2. 以命令内容为核心，减少无意义装饰。
3. 使用适当的信息密度，避免界面过于稀疏。
4. 采用统一的设计 Token 管理颜色、字体、圆角和间距。
5. 减少明显的卡片边框、大面积阴影和重复容器嵌套。
6. 使用柔和背景区分区域，通过排版和留白建立层次。
7. 避免使用大量强调色，仅在选中、主要操作和状态反馈时使用。
8. 保证键盘操作、鼠标操作及拖拽操作的一致性。

### 2.2 推荐配色

默认浅色主题：

| 类型         | 颜色      |
| ------------ | --------- |
| 主背景       | `#FAF9F6` |
| 次级背景     | `#F2F1ED` |
| 内容背景     | `#FFFFFF` |
| 主文字       | `#242424` |
| 次级文字     | `#686868` |
| 边框与分隔线 | `#E5E4DF` |
| 选中背景     | `#EAE9E5` |

深色主题：

| 类型         | 颜色      |
| ------------ | --------- |
| 主背景       | `#171717` |
| 次级背景     | `#202020` |
| 内容背景     | `#262626` |
| 主文字       | `#F5F5F5` |
| 次级文字     | `#A3A3A3` |
| 边框与分隔线 | `#363636` |

上述颜色作为基础设计参考，可在保证统一性的前提下进行微调。

### 2.3 字体与间距

- 常规文字：13–14 px。
- 次级信息：11–12 px。
- 页面标题：15–18 px。
- 命令代码：12–13 px，采用清晰的等宽字体。
- 常规圆角：6–8 px。
- 弹窗圆角：10–12 px。
- 列表行高：根据单行或双行内容控制在约 40–64 px。
- 组件间距统一使用 4、8、12、16、24 px 的间距体系。

避免过大标题、过厚边框和过度留白。

## 三、快捷面板改版

### 3.1 核心目标

快捷面板应该类似 Raycast 或 Win + V，强调快速搜索、快速预览、快速复制和快捷收藏。

窗口应小巧、紧凑，不要变成完整管理界面的缩小版。

默认尺寸建议约 460 × 480 px，支持用户自行调整并记忆尺寸。

### 3.2 页面布局

建议采用以下结构：

```
┌─────────────────────────────────────────┐
│  Pata Commands                   ⚙  ⤢  │
├─────────────────────────────────────────┤
│  ⌕ 搜索命令或剪贴板内容...              │
├─────────────────────────────────────────┤
│  剪贴板     命令库     收藏        12 条 │
├─────────────────────────────────────────┤
│                                         │
│  连接远程服务器                   SSH   │
│  ssh user@192.168.1.10                  │
│                                         │
│  查看 Docker 容器               Docker  │
│  docker ps -a                            │
│                                         │
│  创建 Python 虚拟环境          Python   │
│  python -m venv .venv                    │
│                                         │
├─────────────────────────────────────────┤
│  ↑↓ 选择       Enter 复制    Esc 隐藏   │
└─────────────────────────────────────────┘
```

### 3.3 命令列表设计

每条命令采用简洁的双行布局。

第一行：

- 命令标题
- 可选的收藏标识
- 右侧分类名称

第二行：

- 命令原文预览

具体要求：

1. 代码与标题在字体、颜色上有明显区分。
2. 长命令默认截断预览，但实际复制必须使用完整原文。
3. 鼠标悬停时使用柔和背景高亮。
4. 选中状态比普通悬停状态更明确。
5. 操作按钮仅在悬停或键盘选中时出现。
6. 分类名称以低对比度文本展示。
7. 未手动分类的命令不显示分类标签。
8. 不为每条命令绘制明显的矩形边框。

### 3.4 搜索与筛选

保留顶部搜索框。

搜索时实时筛选列表，匹配文本可以高亮。

保留三个主要标签：

- 剪贴板
- 命令库
- 收藏

切换标签时保持搜索交互的一致性。

### 3.5 自适应高度

当前快捷面板内容很少时，下方会出现大量空白。

建议支持：

- 内容较少时自动收缩窗口的内容区域。
- 设置合理的最小高度与最大高度。
- 内容较多时使用内部滚动。
- 用户手动调整过窗口高度时，以用户设置为优先。
- 不要让搜索结果变化导致窗口频繁跳动。

快捷面板的自动收缩功能应当是可配置的。

### 3.6 键盘与鼠标交互

保留：

- `↑ / ↓`：切换命令。
- `Enter`：复制命令。
- `Esc`：隐藏快捷面板。
- `Ctrl + Shift + V`：全局唤出。

右键菜单、收藏、编辑、移动分类等已有功能不得丢失。

快捷面板拖动和失焦隐藏逻辑必须保持正常。

## 四、完整命令管理界面改版

### 4.1 核心目标

完整管理界面不再采用“左侧导航 + 大面积命令列表”的简陋布局。

参考 VS Code 与 Pieces，改为更符合开发者工具使用习惯的三栏结构。

**分类树 → 命令列表 → 命令详情**

### 4.2 推荐布局

```
┌────────────────────────────────────────────────────────────────────┐
│ Pata Commands                                    搜索   设置       │
├────────────────┬─────────────────────┬─────────────────────────────┤
│ 分类目录       │ 命令列表            │ 命令详情                    │
│                │                     │                             │
│ ▾ Linux        │ 连接远程服务器      │ 连接远程服务器              │
│   ├ SSH        │ ssh user@host       │                             │
│   └ Docker     │                     │ SSH · Linux                 │
│                │ 查看 Docker 容器    │                             │
│ ▸ Python       │ docker ps -a        │ ssh user@192.168.1.10       │
│                │                     │                             │
│ ▸ Git          │ 创建虚拟环境        │ 使用 SSH 连接远程服务器     │
│                │ python -m venv...   │                             │
│ 未分类         │                     │ [复制] [编辑] [AI 注释]     │
│                │                     │                             │
├────────────────┴─────────────────────┴─────────────────────────────┤
│ 本地数据库 · 运行正常                                              │
└────────────────────────────────────────────────────────────────────┘
```

### 4.3 左侧分类树

参考 VS Code 文件资源管理器。

要求：

1. 使用紧凑树状列表。
2. 支持多级目录展开和收起。
3. 文件夹与命令使用统一的缩进规则。
4. 支持右键新建分类、子分类、重命名和删除。
5. 支持将命令直接拖入分类。
6. 拖拽时目标分类高亮。
7. 支持悬停自动展开子目录。
8. 支持分类搜索。
9. 支持保存目录展开状态。
10. 减少不必要的图标和辅助文字。

分类树宽度支持拖动调整。

### 4.4 中间命令列表

采用紧凑列表。

每条命令显示：

- 标题
- 原文预览
- Shell 类型
- 收藏状态

支持：

- 鼠标悬停
- 单击选中
- 双击或快捷操作复制
- 右键菜单
- 多选
- 拖拽排序
- 拖动到分类树

注意：完整管理界面单击命令应优先选中并在右侧显示详情，避免误复制。复制操作使用明确的按钮、双击或快捷键完成。

拖动排序时显示插入位置线与命令缩略卡片。

### 4.5 右侧命令详情

这是本次 UI 改版中非常重要的部分。

用户单击中间列表中的命令，右侧立即显示完整信息。

至少包含：

- 命令标题
- 原始命令内容
- Shell 类型
- 所属分类
- 标签
- 收藏状态
- 备注或注释
- 最近使用时间
- 使用次数
- 复制按钮
- 编辑按钮

未来增加 AI 注释后，在这里展示：

- AI 生成的命令摘要
- 参数解释
- 运行前提
- 风险提示

如果当前 AI 功能尚未实现，不得添加看似可点击但实际上没有功能的按钮。

右侧详情区域必须支持复制完整命令、文本选择、长文本换行或横向滚动。

### 4.6 自适应布局

默认管理窗口建议约 1000 × 680 px。

窗口尺寸较小时：

- 可以隐藏右侧详情面板。
- 允许通过按钮展开详情。
- 不得使命令列表挤压到无法使用。
- 分类栏和详情栏可以拖动调整宽度。
- 记忆用户调整后的布局。

不要强制所有内容始终占据三栏。

## 五、导航与其他页面

现有应用还包含工作流、剪贴板、概览和设置等页面。

这些功能必须保留。

建议：

1. 命令库作为默认首页。
2. 工作流和剪贴板保留独立导航入口。
3. 概览页面简化为紧凑单列。
4. 设置页面采用简洁单列设置布局。
5. 设置入口放置在稳定、容易找到的位置。
6. 避免在多个区域重复显示相同入口。
7. 保持不同页面之间的字体、控件和间距统一。

三栏布局主要应用于完整命令管理页面，不强制其他页面全部采用相同结构。

## 六、组件与架构要求

本次 UI 改版需要整理现有组件，而不是在旧组件上叠加大量临时 CSS。

建议检查并复用：

- CommandList
- CommandItem
- CommandContextMenu
- CategoryTree
- CommandEditor
- CommandDetailPanel
- QuickPanel
- SearchInput
- Toolbar

如果实际组件名称不同，以现有代码为准。

需要建立统一的：

- 主题颜色变量
- 字体规范
- 间距规范
- 圆角规范
- 悬停与选中状态
- 菜单与弹窗样式
- 图标尺寸规范

不应在每个页面中分别维护一套风格。

不要为视觉优化重写已有 SQLite、Repository、Tauri Commands 或剪贴板后台逻辑。

## 七、实施计划

### 阶段一：统一设计系统

1. 检查当前主题、CSS 和组件。
2. 整理浅色与深色主题。
3. 统一字体、颜色、间距、圆角和图标。
4. 清理重复样式及不必要的嵌套容器。
5. 验证现有页面没有样式回归。

### 阶段二：快捷面板优化

1. 优化标题栏与搜索区域。
2. 重构命令列表的视觉层次。
3. 优化分类标签和操作按钮。
4. 调整悬停与选中反馈。
5. 优化内容高度和滚动行为。
6. 验证搜索、复制、收藏、右键与快捷键。

### 阶段三：完整命令管理界面布局

1. 建立分类树、命令列表和详情三栏。
2. 复用现有分类树与命令列表。
3. 增加命令详情预览面板。
4. 支持选中命令实时切换详情。
5. 支持拖动调整栏宽。
6. 处理窄窗口下的响应式布局。

### 阶段四：其他页面统一

1. 优化概览页面。
2. 优化设置页面。
3. 统一工作流和剪贴板页面样式。
4. 检查导航一致性。

### 阶段五：交互与回归测试

重点测试：

- 快捷面板显示和隐藏
- 全局快捷键
- 系统托盘
- 复制命令
- 剪贴板历史
- 收藏
- 命令右键菜单
- 分类拖拽
- 多选与排序
- 详情预览
- 命令编辑
- 窗口尺寸与位置持久化
- 深浅色主题
- SQLite 数据完整性

## 八、最终验收标准

1. 快捷面板明显更紧凑，内容优先。
2. 不再出现大量无意义装饰或空白。
3. 命令卡片具有清晰的标题、代码和分类信息层级。
4. 完整命令库采用分类树、命令列表、命令详情三栏布局。
5. 点击命令即可在详情栏查看完整信息。
6. 用户能够调整分类栏和详情栏宽度。
7. 窄窗口下布局不溢出。
8. 统一浅色、深色主题。
9. 保持现有右键、拖拽、多选、排序等操作正常。
10. 保留全部已有功能和数据。
11. 所有改动经过编译与交互测试。
12. 更新 `docs/development-progress.md`，记录修改和测试结果。

## 九、开发特别要求

本次改版不是重新开发 Pata Commands。

请严格遵守：

- 在现有代码基础上增量修改。
- 先检查当前组件和样式结构，再决定如何调整。
- 不新增没有实际功能的占位入口。
- 不删除或重置已有用户数据。
- 不修改无关业务模块。
- 不为了视觉美化牺牲操作效率。
- 优先保证操作一致性与可维护性。
- 每个阶段独立完成、验证并记录。
- 对尚未实际测试的内容如实说明。

**最终目标：让 Pata Commands 看起来和使用起来都像一款成熟的开发者效率工具，而不再像基础组件拼接出来的管理后台。**
